## 主要不足与改进建议

1. **核心概念的界定与操作化需进一步明确**

- “可靠性税” 作为本文的核心概念，目前仅给出了 τ_r 的数学形式，但对于 “可靠性” 为何选取校准、选择性预测、虚构 - 弃权这三个维度，缺乏理论层面的论证。这三个维度分别对应置信度匹配、选择性回答、前提保真三种不同属性，建议补充选取这三个维度的依据，说明它们是否能够完整覆盖高风险场景下的 “可靠性” 需求（例如是否遗漏了事实一致性、逻辑一致性等维度）。
- “usable accuracy（可用准确率）” 是评估停止规则的关键指标，但目前仅在摘要和引言中简要提及，未给出明确的形式化定义。建议在提出 “可靠性税” 的同时尽早定义该指标，帮助读者理解动态停止规则的优化目标。

2. **相关工作的创新对比可进一步强化**

- 高效推理与早期退出（early exit）领域已有大量研究通过中间层状态预测是否终止计算，与本文的 “动态停止规则” 目标相近。虽然本文属于黑盒设定、基于推理轨迹，但目前相关工作部分仅简要提及 “截断轨迹、早期退出”，未明确对比两者在方法设定、应用场景、核心结论上的差异。建议补充这部分对比，更清晰地突出本文在黑盒自适应推理方面的创新价值。
- 错误前提相关研究部分，目前主要引用计算模型层面的文献。作为 ACL 投稿，建议适当补充计算语言学中关于预设（presupposition）、问题预设谬误的相关研究，增强研究的语言学相关性。

3. **实践动机可进一步具象化**
引言中提到了客服、临床 QA 等高风险场景，但未具体说明 “可靠性税” 在这些场景中会带来怎样的实际负面影响，以及 “可预测的权衡” 能够为部署带来多大的实际收益。例如，固定最大预算会导致多少比例的问题出现过度思考、可靠性下降？动态停止规则在保证可靠性底线的前提下能提升多少可用准确率？可以在引言中给出初步预期或定性的价值阐述，进一步强化研究的现实意义。
### 占位相关
4. **研究范围与边界需更早明确**

- 引言中提到实验覆盖 “[M] families” 的模型，但未说明具体的模型范围、类型（闭源 API / 开源）以及预算控制方式。不同厂商的 “思考预算” 实现机制差异极大（推理努力档位、token 数限制、强制截断等），这些差异可能影响 “可靠性税” 的测量结果。虽然后文提到了基于实际推理 token 数对齐和等计算量对照，但建议在引言中更早说明模型选择的范围和基本设定，消除读者困惑。
- 对于任务类型，仅提到 “四种任务类型”，未说明具体任务与选择依据。建议简要介绍任务类型及其代表性，让读者能够预判结论的适用范围。

5. **部分表述的严谨性可加强**

- 引言中 “sweeping the reasoning budget impairs confidence calibration, and the marginal utility of extra reasoning turns negative” 的表述略显绝对。现有研究的结论并非在所有任务上都成立，建议补充 “在多个研究场景中被观察到” 这类限定，或说明该现象的边界条件。
- 摘要和引言中出现的 “[x]×”“[M] families” 属于占位符表述，正式投稿中应替换为具体数值和内容，避免影响审稿人对研究完整性的判断。
